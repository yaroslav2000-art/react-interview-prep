## Problem: Two Sum
**Pattern:** Hash Map
**Key Insight:** Do not accumulate. Subtract instead.
**Algorithm:**
  1. Loop through the array.
  2. Calculate `complement = target - currentNum`.
  3. Check map: "Have I seen this complement before?"
     - Yes -> Return [map.get(complement), currentIndex]
     - No  -> map.set(currentNum, currentIndex)
**Data Structure:** Map stores { number: index }
**Time:** O(n) - single pass.
**Space:** O(n) - map stores up to n items.
**Gotcha:** Use `<` not `<=` in the loop to avoid accessing undefined.




## Problem: Best Time to Buy and Sell Stock
**Pattern:** Running Minimum (Greedy / One Pass)
**Key Insight:** Don't find the global minimum first. Track the lowest price seen *so far* as you iterate, and calculate profit on the fly.
**Algorithm:**
  1. Initialize `minPrice = Infinity` and `maxProfit = 0`.
  2. Loop through the array once.
  3. If current price < minPrice, update minPrice.
  4. Else if (current price - minPrice > maxProfit), update maxProfit.
**Time:** O(n) - single pass.
**Space:** O(1) - only two variables.
**Gotcha:** 
  - The `else if` is crucial: you cannot sell on the same day you buy.
  - Starting `minPrice` at `0` is a trap; use `Infinity` so the first price always sets the baseline.
  - Sorting is O(n log n) — too slow for interviews.

**Pattern:** Hash Set
**Key Insight:** Track seen values. If you encounter one twice, return true.
**When to use Set vs Map:** Set when you only care about presence. Map when you need key → value.

## Problem: Valid Anagram
**Pattern:** Frequency Map (Hash Map counting)
**Key Insight:** Anagrams have the same length and the same count of each character.
**Algorithm:**
  1. If lengths differ → return false.
  2. Build a Map of char → count from s.
  3. Loop through t: if char not in map → false. Decrement count.
     If any count goes below 0 → false.
  4. Return true.
**Time:** O(n)
**Space:** O(1) — at most 26 letters (or O(k) for unicode)
**Gotcha:** 
  - `return` inside `forEach` does NOT exit the outer function. Use a `for` loop.
  - Store counts, not indices. `map.set(char, (map.get(char) || 0) + 1)`
  - Always do the length check first — it's a free early exit.

## Alternative: Sorting
- Sort both strings, compare. O(n log n) time.
- Valid answer, but frequency map is better.

Valid Anagram — The Pantry Analogy
The idea:
The first string (s) is a pantry. Every character in s is an ingredient, and the count of each character is how many of that ingredient we have in stock.

Building the pantry:
Loop through s. For each character, add one to its count in the pantry.
Example: s = "aab" → pantry has 2 apples, 1 banana.

Consuming the pantry:
Loop through t. For each character in t, try to take one of that ingredient out of the pantry.

If the ingredient isn't in the pantry at all → t needs something s never provided → fail.

If the pantry has it, decrement its count by one.

If the count goes below zero → t asked for more of that ingredient than s ever had → fail.

Finishing:
Since s and t are the same length, if every character in t found its ingredient in the pantry (and no count ever went negative), then every ingredient was used up exactly. Return true.

Why the two checks matter:

!count.has(char) → t has an ingredient that doesn't exist in the pantry at all.

count.get(char) < 0 → t has more of an ingredient than the pantry stocked.

The one-line summary:
Count what s provides, consume it with t, and fail if t ever asks for something missing or asks for more than was stocked.

That's the pattern. It works for Valid Anagram, Ransom Note, and any "does string A contain enough of string B's characters" problem.

## Pattern: Two Pointers
**When to use:**

- Reversing arrays/strings in place

# Algorithm Patterns: Fixed Sliding Window & Running Sum

## Pattern: Fixed Sliding Window
**When to use:** 
- The problem asks for a contiguous subarray or substring of a specific length `k`.
- You need to find the maximum, minimum, or average of that window.

**The Core Idea:**
Imagine a physical window of size `k`. You slide it across the array one step at a time.
Instead of recalculating the entire window at every step (which is slow, O(n*k)), you maintain the "state" of the window as you slide it.

**The "Sliding" Mechanics:**
1. **Expand:** Add the new element entering the right side (`nums[right]`).
2. **Shrink:** Subtract the old element leaving the left side (`nums[left]`).
3. **Check:** Evaluate the current window against your maximum/minimum.

---

## Pattern: Running Sum
**When to use:** 
- You need to repeatedly calculate the sum of a contiguous block of numbers.

**The Core Idea:**
Store the sum of the current window in a single variable (`currentSum`). 
When the window moves, do not use `.reduce()` or a `for` loop to re-add the numbers. 
Just do: `currentSum = currentSum + newElement - oldElement`.

This turns an O(k) calculation into an O(1) calculation.

---

## 🚨 The Pitfall: Over-engineering the Data Structure
In my first attempt, I used a `Map` to store the window's elements and `Array.from(map.keys()).reduce()` to calculate the sum.
**Why this fails:**
1. **Duplicates:** Maps only keep unique keys. If the array has duplicate numbers (e.g., `[5, 5, 5]`), the Map will overwrite them, and your sum will be wrong.
2. **Performance:** Converting a Map to an Array and running `.reduce()` inside a loop creates an O(n*k) time complexity.
3. **Memory:** It uses O(k) space.

**The Rule:** 
> If you only need the SUM of a window, you don't need to store the elements. Just store the running sum in a primitive variable. Keep Space Complexity at O(1).

---

## The Optimal Template (Memorize this shape)

```javascript
const fixedWindowTemplate = (nums, k) => {
  let left = 0;
  let currentState = 0; // e.g., sum
  let maxState = -Infinity; // Initialize carefully based on problem

  for (let right = 0; right < nums.length; right++) {
    // 1. Add the new element to the window state
    currentState += nums[right];

    // 2. While window is too big, shrink from the left
    // (In fixed window, this will only trigger once per loop)
    if (right - left + 1 > k) {
      currentState -= nums[left];
      left++;
    }

    // 3. If the window is exactly size k, record the answer
    if (right - left + 1 === k) {
      maxState = Math.max(maxState, currentState);
    }
  }

  return maxState / k; // Or whatever the problem asks for
};

# Algorithm Patterns: Dynamic Sliding Window

## Problem: Longest Substring Without Repeating Characters
**When to use:** Finding the longest/shortest substring or subarray that meets a specific condition, where the window size is **not fixed**.

**The Core Idea:**
Use two pointers (`left` and `right`) to represent the window. The `right` pointer "explores" by expanding the window one character at a time. If the window becomes invalid (e.g., we find a duplicate), the `left` pointer shrinks the window until it becomes valid again.

**Data Structure:** 
A `Set` is perfect for this problem because it stores unique characters and allows O(1) lookups (`has`), additions (`add`), and deletions (`delete`).

---

## The Algorithm (Step-by-Step)
1. Initialize `left = 0`, `maxLength = 0`, and an empty `Set`.
2. Loop `right` from `0` to the end of the string.
3. **The Shrink Loop:** While the `Set` already contains `str[right]`:
   - Remove `str[left]` from the Set.
   - Move `left` forward (`left++`).
4. **Expand:** Add `str[right]` to the Set.
5. **Evaluate:** Update `maxLength` using the formula `right - left + 1`.

## The Code Template
```javascript
const lengthOfLongestSubstring = (str) => {
  let left = 0;
  let maxLength = 0;
  const charSet = new Set();

  for (let right = 0; right < str.length; right++) {
    const current = str[right];

    // Shrink the window until the duplicate is gone
    while (charSet.has(current)) {
      charSet.delete(str[left]);
      left++;
    }

    // Add the new character
    charSet.add(current);

    // Update maxLength (right - left + 1)
    maxLength = Math.max(maxLength, right - left + 1);
  }

  return maxLength;
};
